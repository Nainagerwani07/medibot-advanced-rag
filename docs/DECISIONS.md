# Decision Log

A short record of each decision: what we chose and why. New entries go at the bottom.

| # | Date | Decision | Alternatives | Why |
|---|---|---|---|---|
| D1 | 2026-09-24 | **Groq** for LLM inference. *Updated 2026-09-25:* Llama 3.x 70B isn't offered on our key; candidates are `openai/gpt-oss-120b` (answers) and `openai/gpt-oss-20b` (router, NL→SQL); final pick on Day 7 after testing | OpenAI, Anthropic, Gemini | Meets "cloud-hosted LLM" requirement; free tier; fast (~0.2 s/call measured); matches bootcamp notebook |
| D2 | 2026-09-24 | **Qdrant in Docker** | in-memory, local file mode, Qdrant Cloud | Index survives restarts; closest to production; Docker available |
| D3 | 2026-09-24 | **qdrant-client directly**, no LangChain vector-store wrapper | `langchain_qdrant.QdrantVectorStore(RetrievalMode.HYBRID)` | Learning goal: see prefetch, fusion and filter directly; RBAC filter placement is easy to audit |
| D4 | 2026-09-24 | **CPU-only** stack: FastEmbed (ONNX) embeddings, MiniLM-L-6 cross-encoder, Docling with OCR off | GPU models, larger rerankers | No GPU on dev machine; PDFs are digital so OCR isn't needed |
| D5 | 2026-09-24 | **One** Qdrant collection + `access_roles` payload filter | One Qdrant collection per document collection | The brief asks for metadata-filtered RBAC; admin cross-collection search stays a single query |
| D6 | 2026-09-24 | Role comes **from the JWT**, not the `/chat` body | Trust `role` in the request as the brief literally says | Otherwise anyone can send `role: admin`; server-side authorization |
| D7 | 2026-09-24 | `doctor` can access `nursing` | Only clinical + general, as in the brief's role table | The brief's data-source table lists doctor under nursing; the two tables disagree, and we follow the more specific one |
| D8 | 2026-09-24 | Router's target-collection guess is used **only for the refusal message** | Using the router as the access check | An LLM router can be prompt-injected; the Qdrant filter is the real boundary |
| D9 | 2026-09-24 | SQL executes read-only, SELECT/WITH only, row limit | Execute whatever the LLM returns | LLM output is untrusted input |
| D10 | 2026-09-25 | **uv** for Python and dependencies; Python 3.12 pinned; `uv.lock` committed | pip + venv, poetry | Fast, reproducible installs; manages the interpreter (system Python is 3.10) |
| D11 | 2026-09-25 | **src layout**: `backend/src/medibot/` installed as a package | Flat `backend/app/` | Same imports from scripts, tests and the API; tests run against the installed package |
| D12 | 2026-09-25 | **Quality gates:** pre-commit (gitleaks + custom Groq rule, ruff, large-file, private-key, no-commit-to-main); Claude hooks (branch guard, ruff on edit); `/start-session` and `/end-session` skills | Rely on discipline / CLAUDE.md text only | Enforced checks beat reminders. Testing showed default gitleaks **missed a bare Groq key**, hence the custom rule |
| D13 | 2026-09-25 | **Qdrant v1.19.1** pinned, ports bound to 127.0.0.1, named volume, no container healthcheck | `latest` tag, 0.0.0.0, bind mount | Version stays compatible with the client; no API key so it must not be network-reachable; image has no curl, so readiness is checked from Python via `/readyz` |
| D14 | 2026-09-25 | Dependencies added **on the day they're first used** | Install everything on Day 1 | Each dependency comes with its reason, and the git history shows why it was added |
| D15 | 2026-09-27 | **CPU-only PyTorch wheels** via a `pytorch-cpu` uv index (`explicit = true`) for torch/torchvision | Default PyPI torch (CUDA build) | Docling pulls torch; the default wheel is the CUDA build (+~4 GB of NVIDIA libs, venv 5.9 GB → 1.5 GB). No GPU here (NF2), and it keeps the future Docker image small |
| D16 | 2026-09-27 | **PDF heading levels come from font size** (26 pt title, 16 pt L1, 12.5/10.8 pt L2, 9.3 pt callout label nested under the current section), applied after Docling parsing | Trust Docling's levels (all L1); infer from numbering (`1.`, `A.`, `SOP N`, `QN.`); PDF bookmarks | Docling's PDF layout model detects headings but not their depth. Numbering differs per file and some sections are unnumbered; the PDFs have no bookmarks. Font sizes were consistent across all 11 PDFs (Day 2 inspection). Markdown already has correct levels. Needed for R2.3 |
| D17 | 2026-09-28 | Chunk **`max_tokens = 256`** (bge-small tokenizer), counted **including** the heading prefix | 512 (model max), 128 | Day 3 profile: every text section fits in ≤ ~230 tokens with headings, so 256 never splits text; only large tables split, into row groups that are more precise to retrieve than a 512-token chunk covering ~8 drugs. 128 would split 11 text sections. Revisit with the eval set (Day 6) |
| D18 | 2026-09-28 | Tables serialised as **one `column: value` line per row** (`KeyValueRowTableSerializer`), split between rows with the heading prefix inside the budget (`_HeadingAwareChunker`); inline `**bold**`/`` `code` `` stripped from Markdown before parsing | Docling triplets (default); Markdown table + repeated header | Measured per formulary row: triplets 68 tokens and the whole table is one line, so splits cut mid-cell; Markdown splits on rows but its separator line costs 142 tokens per piece; key: value 44 tokens and each row stands alone. Inline formatting made Docling split paragraphs into fragments. Chosen by the user (option C) |
| D19 | 2026-09-28 | BM25 **`avg_len` computed from our chunks** (mean stemmed words of `embed_text`, ~49) and passed to FastEmbed `Qdrant/bm25`; IDF left to Qdrant (`Modifier.IDF`) | FastEmbed default `avg_len = 256`; computing IDF ourselves | BM25 length normalisation compares each chunk to the corpus average; with 256 every chunk looked ~5x shorter than average. Query vectors are weight 1.0 per term, so only the document side changes. Qdrant keeps IDF correct as points are added. Day 4 exploration showed table column words (dose, route) top the TF weights, so IDF is what lets rare terms like drug names win |
| D20 | 2026-09-28 | **Deterministic point ids** (`uuid5(source_document#chunk_index)`) and a **full collection rebuild** on every `ingest.py` run | Random uuid4 ids; incremental upsert | Re-running ingestion overwrites instead of duplicating (checked: random ids gave 8 points for 4 chunks). A rebuild means a chunking change can't leave stale points behind; 268 chunks index in ~25 s on CPU, so there's no reason for incremental updates yet |
| D21 | 2026-09-28 | **Two-part RBAC filter** (`access_roles` contains role AND `collection` in `ROLE_COLLECTIONS[role]`), set on **each prefetch and the outer query**; unknown role raises `ValueError` | `access_roles` only; top-level filter only; filter after the search | Day 5 showed the top-level filter alone works (Qdrant pushes it down), but setting it on every stage doesn't depend on that behaviour. The collection check catches a chunk indexed with stale `access_roles` (mutation test: 7 failures without it). Post-filtering left 0 chunks for a nurse and brings forbidden text into the process. No silent "no filter" path for a bad role |
| D22 | 2026-09-28 | Qdrant **RRF defaults (k=2)**, `prefetch_k = 20` per retriever, final `k = 10` | RRF k=60; weighted/score fusion (DBSF); larger prefetch | Fusion by rank, since cosine (0.46–0.70) and BM25 (0–14) aren't on one scale. k=2 favours 1st place in either list; whether k=60 or a different prefetch is better is measured on the Day 6 eval, not guessed. k=10 is the broad set the reranker cuts to 3 (R4.2) |
| D23 | 2026-09-30 | Reranker **`Xenova/ms-marco-MiniLM-L-6-v2` via FastEmbed `TextCrossEncoder`** (ONNX), scoring **heading path + text**; top-10 → top-3 | sentence-transformers CrossEncoder (torch); MiniLM-L-12; bge-reranker-base; section title + text | Same ONNX runtime as our embedders, no torch at query time (D4). Eval: L-12 2x slower for +0.03 hit@1, bge-base 8x slower and worse. With only the section title the reranker lowered hit@1 (two protocols share "Pharmacological management"); the heading path raised it to 0.87 (docs/EVAL.md) |
| D24 | 2026-09-30 | **`gpt-oss-120b` for answers and SQL→answer, `gpt-oss-20b` for router and NL→SQL**; temperature 0, `reasoning_effort="low"`, 2048 completion tokens | 120b everywhere; 20b everywhere | Finalises D1. The 20b is enough for JSON routing and SQL on a 2-table schema (7/7 test questions correct); answers are what users read. Low effort + generous limit avoids empty answers from hidden reasoning tokens |
| D25 | 2026-09-30 | **JWT (HS256, 8 h) with `sub` + `role`; bcrypt hashes of the demo accounts in code; token rejected unless its role matches the account's current role; `/chat` body `role` ignored**; secret from `MEDIBOT_JWT_SECRET` (random per process if unset) | Plain-text passwords; sessions in memory; trusting body role | R1.4/D6. Role-matches-account means a leaked signing key alone can't mint admin for a nurse account, and a role change takes effect without waiting for expiry. `/collections/{role}` is allowed for your own role (admin: any) |
| D26 | 2026-09-30 | **Refusal rules**: SQL for non-billing/admin → refuse; router targets *only* blocked collections → refuse without searching; mixed question → answer the allowed part + a note naming the blocked collection; response adds `blocked: bool` | Refuse whenever any target is blocked; always search | R1.3 message comes from the router guess (D8), but the data boundary stays the Qdrant filter. Refusing a whole mixed question hid an answer the nurse was allowed to get. `blocked` lets the UI style refusals (R7) without parsing text |
| D27 | 2026-09-30 | SQL safety in three layers: `clean_sql` (one statement, SELECT or a real `WITH x AS (` CTE, no write/DDL keyword) → `mode=ro` + `PRAGMA query_only` → sqlite **authorizer** allowing only SELECT/READ/FUNCTION; 50-row cap; schema prompt lists distinct category values and the data's date range | Prompt instructions only; regex only | D9/NF1. Each layer was tested with the others bypassed. The test suite caught `clean_sql` accepting "I can't help **with** that" as a CTE. Listing values and the date range fixed the Day 1 items ("escalated", "last month" = relative to 2024 data) |
| D28 | 2026-10-01 | **Adversarial harness against the live API** (`attack_demo.py`): 8 attacks, each also sends `role: admin` in the body; pass = no source outside the role, no canary string from a restricted document in the answer, no SQL for non-SQL roles; plus a "router skipped" pass straight into `HybridRetriever` | Only manual screenshots; only unit tests with fakes | R1.5 needs documented attacks; canary strings check the *answer text*, not just sources. The router-skipped pass shows the Qdrant filter holds on its own, since in the live run the router refuses first and would otherwise hide whether layer 2 works |
| D29 | 2026-10-01 | **Frontend: Next.js 15 App Router, one client page, plain CSS, token in `sessionStorage`, a tiny React-element Markdown renderer** (bold, lists, code) | Tailwind / component library; `localStorage`; `dangerouslySetInnerHTML` with a Markdown library | R7 is 5% of the grade: small and dependency-free. sessionStorage ends with the tab. LLM output is rendered as React elements, so it can't inject HTML. The UI shows the role from the server response; hiding a collection in the UI is cosmetic, the API is the boundary |
